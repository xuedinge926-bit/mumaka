## 模型与导入接口

歌曲为歌词、作曲、表演、制作、愿景、语境；乐曲为素材、结构、表演、制作、愿景、语境。界面所有中文维度均两个字，帮助说明含范围、取证要点、排除项与防重复计分边界。

内部使用新的中性轴标识与独立模式草稿；卡片适配器仅将六个展示位置传入原图表组件，绝不转换旧评分或持久化语义。新草稿schemaVersion=2，modelVersion=`v0.40.0`，definitionVersion=`v0.40-six-dimensions-1`；数值权重版本`v0.38`，工作簿来源版本`v0.38.1`。

计算：星级tick=半星，权重tick=半百分点。单模式总分为整型积和/200，以BigInt作ROUND_HALF_UP。混合前四维分别乘人工艺术比重；愿景与语境只用共同的专辑星级各一次，分母40000，最终只舍入一次。曲目数与时长不参与混合比重。

新数据包接口为完整JSON：`schemaVersion`、`sourceVersion`、`weightVersion`、`sourceSha256`、`families[34]`、`genres[565]`、`anchors[168]`；各风格必须含 `profiles.song` 和 `profiles.instrumental`，并分别保留 `weightsTicks[6]`（索引为null）、`applicability`、`trialAllowed`、`source`、`rationale`、`reviewStatus`、来源sheet/row。可从数据管理导出当前包作结构参考，再导入替代包。缺源或无效包明确拒绝，不推算补值。

复现提取（源文件仅放自己电脑，不上传）：

```bash
python3 scripts/import-v038.py SOURCE.xlsx --r3 CN_R3.xlsx --split --out src/data/v038
```

批准状态必须带明确的人审 `approval.reviewer/reviewedAt/evidence`；定义争议和不适用组合仍不可绕过。导入数据不会自动执行发布。正式结果还要求整碟试听、六维证据与人工审核；保存的正式快照记录显式批准及模型/权重snapshot。

## 存储、历史和备份

- 原库 `nmc-workbench-v1` / version1 与V0.35研究库不升级、不清空。原V0.19精确算法和旧历史显示原样保留。
- 新库 `mumaka-v040` / version1 单独保存双模式草稿、不可变快照、工作目录与旧库保护副本。写入串行，拒绝旧revision覆盖；删除草稿不删除快照。
- 新旧作品和备份入口均保留。V0.40完整备份、单份评分JSON及冻结snapshot均可恢复，按ID去重，冲突整份回滚；只复制旧作品资料时，新星级为空，不映射旧表意或声音。
- 所有历史快照含当时的具体风格及权重数值、两模式星级、混合艺术比重、总分、模型/定义/权重版本、来源哈希与完整性哈希。读取不按当前目录重算。
- 数据只存在各自浏览器origin。本地文件、本机8765和原Pages互不自动共享，换入口前导出完整备份。

## 验收与发布

单元、Python基准、构建与完整浏览器检查在PR工作流执行。浏览器涵盖新双体系/独立草稿、权重切换、混合比重、实时总分与六瓣图、PNG三比例、JSON往返、历史快照、320/390px手机、file://单文件及原工具归档回归。测试用唱片均为固定技术样本，不是实际评分。

开发主机已通过291项单元、18项Python基准和33项导入服务测试，标准与单文件构建及公开内容扫描通过。当前自动化Chrome启动被主机限制，浏览器验收以PR的GitHub Actions实际结果为准，失败不发布。测试输出及截图在Actions的browser-test-evidence产物中保留14天。测试依赖更新到Vitest4.1.12后npm审计为0个漏洞。

构建命令：`npm test`、`npm run test:reference`、`npm run test:import`、`npm run build`、`npm run test:e2e`、`npm run build:standalone`、`npm run check:public`。发布沿用 `.github/workflows/pages.yml`、`gh-pages`分支与原Pages网址；PR只检查，main全绿后发布。原`site/`发布留档不覆盖。
