# 统一工作空间与国内来源：交付记录

本轮以用户最新修订为准：第一优先级仅网易云、QQ 音乐；第二优先级保留 Spotify、Apple Music；Bandcamp 保留，不扩展第三批平台。基于现有项目修改，没有新建另一套演示应用。

## 导航与操作状态

首页仍是默认入口。“专业工作台”按钮现在只展开全局导航，地址和当前内容不变。首页、作品库、评分记录、风格管理、评分卡、数据管理、设置都在同一应用框架中。

- 桌面侧栏可展开／收起并保留当前视图，使用约 200ms 的简单过渡；支持减少动画偏好。
- 手机使用覆盖式抽屉，可点关闭按钮／遮罩或按 Escape 关闭，键盘焦点返回菜单按钮。导航触摸目标保持可操作尺寸。
- 顶部菜单随页面滚动保留，评分页较长时仍能打开。工作区带返回与首页入口，评分步骤也保留原有切换。
- 风格管理只读浏览现有分类，按一、二级搜索选择。只有明确点击应用，才修改当前草稿的风格 ID；无编辑权重数据库的入口。
- 全部视图使用 hash 路由，兼容原 GitHub Pages 项目路径和单文件，不需要服务端路径重写。

| 地址片段 | 内容 |
| --- | --- |
| `#/home` | 默认首页 |
| `#/library`、`#/ratings`、`#/genres` | 作品库、评分版本、只读风格库 |
| `#/cards`、`#/data`、`#/settings` | 卡片入口、备份／CSV、新作品偏好 |
| `#/album/{ID}/confirm`、`rating`、`card` | 同一草稿的资料、六维和卡片步骤 |
| `#/snapshot/{ID}/{步骤}` | 指定历史快照，始终使用冻结结果 |

路由实际调用 History API，监听浏览器 `popstate` / `hashchange`，支持后退、前进、深链接和刷新。首次直接进入子页面也有返回首页的兜底；不存在的记录显示可恢复的提示。

草稿留在同一个应用状态与原 IndexedDB 中；离开编辑器、或浏览器后退先于保存防抖触发时，会完成保存队列，再加载另一个 ID。过时的路由加载不会覆盖新视图；其他草稿保持独立。首页可继续当前评分，“快速评分”优先恢复尚未生成卡片的当前任务，手动添加明确创建新记录。

## 网易云与 QQ：已实现和未验收的边界

新增了来源适配、QQ／网易分享文字与短链识别、同平台公开跳转、JSON-LD / 公开内嵌 JSON / 可读 DOM 解析、来源显示和确认后的同库保存。保留原始短链、实际元数据页面及获取时间；外部标签不映射成内部风格，缺失信息不猜填。新来源字段是兼容扩展，旧备份仍可读取。

只读取公开资料，不调用逆向音乐接口，不执行网页 JavaScript、不传登录 Cookie、不绕过验证码／robots 或访问限制。短链只跟随同一音乐平台的已允许域名，外域、循环及过多跳转拒绝。歌曲与歌单不会自动当作专辑。

网易旧版公开专辑 DOM／曲目 JSON、QQ 公开 JSON、通用 MusicAlbum 结构化数据的解析与真实本机 HTTP → 前端确认 → 数据库 → 评分卡流程已由固定样本验证。测试曲目是明确的合成内容，不是用户专辑的真实抓取结果。

**用户提供的两条真实链接尚未采集成功：**

| 来源 | 实网尝试 | 结果 |
| --- | --- | --- |
| QQ《2号线｜绿日长夏》 | `https://c6.y.qq.com/base/fcgi-bin/u?__=2zNumVIuq73g` | 当前云环境出口 CONNECT 403；新 CLI 退出码 1，显示无法连接来源 |
| 网易云同专辑 | `https://163cn.tv/bjQO3xkl` | 同样被当前出口拒绝；新 CLI 退出码 1 |

这发生在访问源站之前，不能据此推断平台本身是否允许读取，也不能证明当前网页结构已适配。真实落地链接、源站 robots、当前 HTML 字段、曲目完整性和图片访问都还需实网核验。相关域名已加入环境配置草稿，运行时尚未应用；需在环境设置应用后继续验证。没有把两个适配器报告为实站接通。

GitHub Pages 保留静态部署：在线版通过导入 Python 工具生成的 JSON 使用；直接粘贴采集在本地同源服务 `npm run local` 中运行。Spotify 官方搜索与 Apple Music 的已有路径保留，本轮未要求新凭据。

## 运行与复验

```bash
npm ci
npm run local
# 浏览器从终端显示的本机地址打开
```

```bash
npm test
npm run test:reference
npm run test:import
npm run build
npm run test:e2e
```

不同 origin 的 IndexedDB 仍相互隔离；从原在线地址换到本机时，先导出完整备份，再在新地址恢复。路由只增加 hash，不改变原站 origin，因此应用导航不会切换数据库空间。
