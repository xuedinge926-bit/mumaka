# 本轮交付与验收

本轮在现有项目中实现免费导入及工作流优化，保留原评分引擎、558 项风格数据、数据库名称／版本、历史快照和当前评分卡。已先合入远程 `main` 的 16 个已有 Spotify 相关提交，基线为 `98509a5`，未丢弃用户提交历史。

## 已真实运行的能力

- 本地 Python 生产服务与 React 网页同源运行；通过链接获取后可确认／编辑名称、音乐人、年份、发行形式、曲目及封面，然后创建新记录进入风格选择。
- 静态网页可读取 Python 工具的元数据 JSON；无法获取、不支持来源或没有服务时可继续手动添加。
- 导入保存来源 URL、元数据 URL、获取时间、适配器、参考标签与发行形式；嵌入可用封面。缺失字段不编造，外部标签不自动选择内部风格。
- 可能重复的作品可打开原记录或明确另建记录，不覆盖旧评分。已发表记录保留冻结结果，草稿删除保留评分历史。
- 首页提供快速评分、专业工作台、链接／手动添加、搜索和近期记录；专业工作台分作品库、评分记录、数据、设置和卡片工具。
- 作品库支持搜索、筛选、排序、打开、复制与删除草稿；全量 JSON 备份恢复和 CSV 导出继续可用。新作品可设置默认比例及常用排序偏好。
- 多风格 EP 可从已选主风格填入曲目，再逐曲或批量修改。每曲等份／核实时长的原汇总方式保留，重选“多种风格”不会重置已选时长模式。未加入不明比例的新公式。
- 普通原创、翻唱、新旧混合及旧作重录仍按原来源政策；特殊情况需要确认，不提供手调权重。六维半星、键盘／触摸、N/A、零理由评分与自动保存保留。
- 现有卡片可返回修改星级并更新、填写可选短评、导出 4:5／3:4／1:1 PNG。只增加独立 `ScoreCardData` 边界，没有采用未选卡片方案或新编辑器。
- Spotify 可选代理对齐实际 Node 部署入口与前台 `action` 契约，精确 CORS；前端代理请求含总超时，失败后恢复手动操作。

## 仍受外部限制的部分

**两个真实来源尚未完成成功采集验收。** Apple / Bandcamp 的首批适配器已接入真实本地 HTTP 流程，解析与全流程使用明确标记的固定样本验证。当前云环境出口代理对相关网站返回 CONNECT 403。已从真实生产网页尝试真实 Apple Music 链接，实际显示网络失败，再成功转为手动添加；没有把该请求写成成功案例。

访问所需域名已保存到云环境配置草稿，尚未应用到当前运行时。放行后仍需以真实链接核对名称、封面、年份、完整曲目，再确认来源可稳定使用。Spotify 真实账号、Vercel 线上函数及实时搜索尚未验收；其存在不构成基础功能的前提。

网易云、QQ 音乐、Spotify 公开网页的免费完整曲目采集和 Bandcamp 自定义域名本轮未接入。不会绕过限制。GitHub Pages 使用 JSON 工具方案，无法直接运行 Python，也不会访问用户电脑上的 HTTP 服务。

## 本地启动与数据说明

```bash
npm ci
npm run local
```

在自己的电脑打开终端显示的本机地址。只使用 Pages 时，在仓库根目录运行：

```bash
python3 -m tools.album_import '专辑HTTPS链接' -o album.json
```

然后在页面导入元数据 JSON。详细条件见 [导入说明](../ALBUM_IMPORT.md)。不同地址、端口和浏览器的数据相互隔离，切换前应先备份，在新地址恢复。新评分卡接口见 [ScoreCardData](../SCORE_CARD_DATA.md)。
