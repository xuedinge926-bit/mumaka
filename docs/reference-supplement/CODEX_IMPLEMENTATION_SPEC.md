# V0.19-RC1 · Codex实施规格（用于编写实际应用）

> 不要自动从艺术家名望、用户偏好、其他网站榜单、专辑年份或先前AI生成的星级推断正式评分。评分必须由人工负责，系统只执行规则、显示证据、计算权重并审查材料完整性。

## 一、产品定位

- 编辑评审工作台，第一阶段为本地单机/本地数据优先（不涉及在线账号、云端多人协作），将来可扩展社区和公众号/小红书图片输出。
- 主要内容：中国大陆及华语市场流行、摇滚、民谣、独立、R&B、说唱、电子等唱片；全球风格主库可被完整搜索使用。
- 专辑/EP为最小评分单位；不是单曲分数加权平均。
- 首版需要一张静态可导出的**六维风向玫瑰图**以及可编辑权重清单；避免图表取代评分数字、证据和规则记录。

## 二、系统架构建议

1. **版本化只读数据**：`genre-weights-v0.17-frozen.csv`、`CHINA_MARKET_INDEX_33.csv`、`REGIONAL_FOLK_DECISION_REGISTER.csv`和政策文件。导入时检查行数、哈希、字段和值；不在UI中直接覆写基础表。
2. **类型选择服务**：搜索中国市场33个入口或查询完整全球558条；前者是“常用导航”，不是新风格层级。保存`index_entry_id`与`global_genre_id`；校园民谣允许多个索引入口指向同一全球ID。
3. **整碟元数据**：专辑唯一ID、确切版本、年份、发行类型、曲目/时长、作者及首次发表/传统来源、音乐语言与地域标签。任何历史归属争议留待核实。
4. **人工分类依据**：主风格、音乐结构证据、相邻风格为什么不选；仅跨家族真实混合时开启“逐曲风格合成权重”。
5. **修正引擎**：先定性文化审查（每次必做）；然后来源修正（非零须词/曲来源台账）；再检查文化数值修正（当前获批档案为空，默认0）；保证比例、零和、上限。
6. **六维编辑器**：每维0.5—5星、N/A（限明确适用场景）、未评价；评级者为每维单独记录证据与反证。4.5/5要求：支撑曲目、艺术依据、为何不是低半星、是否覆盖全碟。
7. **计算/可视化**：显示原始权重、修正后权重、评分精确值、half-up两位总分、玫瑰图；若未评价则不能展示正式总分。
8. **证据/审计**：草稿、研究候选、结构化发表条件满足、已正式发布（最后一种必须由人工审批）。所有修改记录用户、时刻、版本、前后值、审批依据与原始SHA；历史数据不可静默迁移。

## 三、最小数据类型

```typescript
// 示例类型，供Codex在项目中实现真正的校验。不能以UI隐藏字段替代服务端验证。
type Dimension = 'lyrics' | 'composition' | 'performance' | 'sound' | 'vision' | 'context';
type Star = 0.5 | 1 | 1.5 | 2 | 2.5 | 3 | 3.5 | 4 | 4.5 | 5;
type ReviewValue = Star | null; // null必须结合assessmentState才能分清N/A/unassessed
type AssessmentState = 'scored' | 'not_assessed' | 'not_applicable';

type AlbumReview = {
  releaseId: string;
  editionId: string;
  modelVersion: 'V0.19-RC1';
  baseDataSha256: string;
  genre: { indexEntryId?: string; globalGenreId: string; audibleEvidence: string; alternateRejectedReason: string; };
  tracks: Array<{ id:string; title:string; durationSec?:number; lyricsProvenance:string; compositionProvenance:string; genreId?:string; }>;
  languageTags: string[];
  cultureQualitativeReview: string;
  sourceCorrectionPreset: string;
  numericCulturalProfileId?: string;
  stars: Record<Dimension, { state:AssessmentState; value:ReviewValue; evidence:string; } >;
  status: 'draft' | 'research_candidate' | 'publish_eligible' | 'published';
  reviewedBy?: string;
  approvedBy?: string;
};
```

`globalGenreId`才持有权重；`indexEntryId`只能作为搜索导航和审计提示。对`not_assessed`不输出可发表总分，对`not_applicable`记录理由并重新归一化动态权重。

## 四、路由判定（不得反向按得分选择）

- 方言民谣：先判断是当代民谣、独立民谣、民谣流行等，再附方言标签，不创建“方言民谣加权”。
- 方言摇滚：先判民谣摇滚、另类摇滚、流行摇滚等；地名和方言不自动增加文化/语境。
- 校园民谣：需原声民谣歌曲语言 + 明确历史创作传统证据；索引`cn-index:campus-folk`→`genre:contemporary-folk`。不是对毕业/青春主题的自动分类。
- 西北民谣：若持续可听到地域民歌声腔等，目前`genre:contemporary-folk`为临时主风格、额外保存`cn-review:northwest-folk`候选标签。
- 西北民歌摇滚：同理用`genre:folk-rock`或依据真正主体另选具体摇滚类型，并记录候选标签；不能根据名字强制民谣摇滚。
- 中国风/古风：只有传统音乐材料实质参与声音/旋律/结构时才允许条件性`genre:chinese-style-pop`；仅古诗歌词或古装视觉不充分。
- 用中文演唱的R&B、另类摇滚或House：默认使用国际既有风格；不复制中文特供百分比。

## 五、计算规范

```
整碟基础权重W：一张专辑一个二级风格；真跨家族则合成一组整碟W
定性文化理解：必做，默认不改变任何数字
数值文化修正C：零和、只针对动态前四维、L1≤4；当前批准档案空，默认全部0
作词N/A/表演N/A：先在W+C中移除相应维度，将剩余适用动态维度比例归一至70
创作来源修正S：零和、只针对动态四维、L1≤16（标准≤12），不得转移N/A维度
来源与文化修正共同预算：L1(S)+L1(C)≤16
最终动态权重≥5%（仅适用维度）；愿景与语境各15%；总百分比为100
总分（满分10）：sum(stars_i * final_percent_i)/50，仅最终展示两位，ROUND_HALF_UP
```

- 使用有理数或精确十进制，不以浮点误差决定两位分数。
- 多曲风：**只混合权重，不平均曲目星级**；时长合成只在有可靠时长资料时启用，默认按曲目等份。
- 任何非零文化数值修正：当前禁止发布，待后续新增实际获批的文化档案与专门回归测试。
- 先前对迪伦、罗大佑、许嵩、周杰伦的候选星级**不能直接成为自动评分的真值数据**。

## 六、UI构成（第一阶段）

| 屏幕 | 必要组件 | 验收点 |
|---|---|---|
| 作品与版本 | 作品名、艺术家、版本、曲目来源 | 同一发行的不同版本不能覆盖 |
| 风格选择 | 中国市场33快捷入口，全球558搜索，其他可审标签 | 可见基础权重ID、条件状态与边界提示 |
| 文化与来源 | 定性文化记录、逐曲词曲来源、修正档位及合并预算 | 展示“未审核／未批准”且不允许直接发布 |
| 六维评审 | 6×半星选择、N/A/未评价、独立证据输入 | 4.5/5强制支撑理由，不允许复制声望作证据 |
| 结果与玫瑰图 | 六维星级、实际权重、10分总分、玫瑰图、证据摘要 | 玫瑰图可静态PNG/SVG导出；未经批准的结果带“研究候选”标签 |
| 版本历史 | 原数据哈希、旧新评分、修正理由、审批记录 | 不可静默重算已发布成绩 |

## 七、必须通过的验收用例

1. 33个入口但只有32个独立底层风格ID；两个入口共用同一百分比时不能创建重复配置。
2. “方言”不会自动改变权重；“西北”待审标签不能作为新风格ID送入评分器。
3. “校园民谣”必须凭听感及历史传统证据进入，不能只凭校园歌词或艺术家学历。
4. 中国风与另类流行两个条件风格，无专辑音频/结构性说明不得确认。
5. 来源/文化修正不超预算、不涉及愿景语境、不让任一适用动态权重低于5%。
6. Lyrics N/A和极罕见Performance N/A正确归一；未评价不等于N/A，不生成正式分数。
7. 跨家族只有一个全碟六维星级；按等曲数或时长合成权重，计算总分可以复现。
8. 相同六维星级全为4的专辑，任何有效权重结果必须为8.00。
9. 5星需要独立维度证据和为什么4.5不够；没有证据不能转正式发布。
10. 历史版《之乎者也》《范特西》等旧成绩保持原快照，改规则必须生成新审计版而不是直接覆盖。
11. 不允许通过勾选“已批准”直接绕过尚为空的数值文化修正档案注册表。
12. 数据和计算代码在不联网环境可运行；外部音频与市场证据不能由程序伪造。

## 八、实现顺序建议

**M1** 只读风格导入/搜索与版本化；**M2** 规则计算器和测试；**M3** 人工评审/来源台账及发布门禁；**M4** 六维玫瑰图和图文导出；**M5** 市场标签实际使用率验证和跨流派盲听校准。

M1–M4可开始编写；M5是研究工作，不能伪装成软件开发自动完成。
