# 给 Codex 的执行任务书｜新乐评主义 Web App 第一轮产品重构

> **在现有可运行 React 项目上做重构，不要新建项目，不要推倒评分引擎，不要重写 V0.19 计算规则。** 先阅读当前仓库代码、README、评分引擎、数据类型与测试，并保留原有用户数据。
>
> 优先级：**好用、简洁、直观 > 信息展示数量**。产品是私人专辑评分工具，不是模型手册展示网站或审核流程管理后台。

## 0. 产品核心原则（必须执行）

1. **前台只显示用户需要作出的选择和最终结果；后台负责其余全部计算。** 取消在正常工作流中展示规则来源、风格ID、基础权重、权重修正公式、绝对变动预算、数据哈希、来源台账、模型审计口号等。
2. **不改变算法。** 保持六维、十档半星、全球二级风格数据库和中国市场索引、文化/来源修正、N/A、跨家族逐曲权重合成、精确计算以及历史可复算能力。所有修正不能因为UI精简而被跳过或随意猜测。
3. **删除冗余交互。** 没有强制评分理由、20字或其他最少字数、多个单独半星控件、裸露的权重数字输入框、冗长的说明文字。每个屏幕只给当前步骤相关的操作。
4. **只做一次主线操作：搜索专辑 → 确认信息和风格 → 六维打星 → 评分卡与导出。** 新建评分用3个主要工作页面加一个极简首页完成；用户可以返回修改，不丢失数据。
5. **优先复用既有代码与数据，不造新风格、不重写基线、不用模拟数据伪装成真实Spotify查询。** 先运行现有测试建立基线，再改造UI，完成后回归测试。

## 1. 页面与导航

### 首页：只保留必要操作
- 页面中央/上部一个大搜索框：「搜索专辑或音乐人」。
- 显示紧凑的「最近编辑」项目，不展示长篇介绍、口号、六维原理、模型研发进度或十几张功能卡。
- 搜索结果每行只显示：**大约64px封面、专辑名、音乐人、发行年份、发行版本/Album或EP（如有）**；点选即可进入。
- 搜不到时提供低强调入口：「手动添加专辑」。手动添加只需专辑名、艺人、年份/封面（可稍后补），不要恢复大量必填表单。
- 顶部保留简洁品牌名称和一个不抢眼的设置入口；不做花哨仪表盘。

### 第一步：专辑确认 + 风格选择（同一页面）
- 从Spotify选中后显示**醒目的大封面**和专辑名、艺术家、年份、具体发行版本、曲目清单；必要字段可就地编辑。
- 不将「作品信息」「曲目与来源」拆成两个大型步骤。曲目默认折叠为「查看曲目（N首）」；支持简单更正。
- 「中国 / 其他地区」以轻巧单选显示，仅用于**风格推荐排序**，不得影响权重、星级和文化修正，也不得以Spotify可播放地区推断音乐创作地区。用户可以切换。
- 接着显示风格选择：**一级风格 → 二级风格**，两层均支持可输入搜索和展开选择；二级选择的候选必须受一级筛选。允许通过全局搜索一个二级风格后自动定位到对应一级。
- 保留全球现有一级/二级结构；33个中国市场索引只负责中国优先排序和别名映射，**不是单独的中国风格页或第二套百分比**。用户始终看见一棵统一风格树。
- 如果确有可信的外部风格信息，可在选择器上方给出「建议：R&B（来源：Spotify／所用数据源）」并允许「采用」或「自行选择」。**重要：Spotify Web API不保证提供可信的专辑级风格；不得将艺人流派直接伪装为专辑流派，更不得猜测后声称来自Spotify。无可信字段时隐藏该模块。**
- 仅一个清晰的「下一步：评分」主按钮。

### 多风格情况：用户只看得到简单的单选/选择操作
- 默认「一种主风格」，绝大多数专辑只选一个二级风格。
- 另有「多种风格」单选选项；选中才展开简化界面。**不要默认铺开全部多风格计算规则、权重分布和专业术语。**
- 如果整张真实跨多个一级家族，显示曲目清单，每一行提供搜索式风格选择；可批量给多首曲目指定同一风格，未指定曲目有明显但简短的提示。
- 后台按现有V0.19规则对逐曲风格**合成权重**，默认每曲等份；如已有合法可靠时长资料且用户明确需要，才在「更多选项」提供按时长。**仍然只给整张专辑打一组六维星级，不给每首曲目打星或平均单曲分数。**
- 对同家族混合/General fallback遵守既有模型；如引擎需人工确认，简短提示，不显示算式。专辑很多曲目时支持批量分配和收起/展开，避免几十行表单占满屏幕。

### 创作来源：隐藏复杂修正，保留最少必要选择
- 不在前台出现百分比滑杆、来源修正五档代码、文化数值修正按钮或“±几个百分点”的表格。
- 仅在无法自动从可靠数据确定时，用一句直白选择：「这张专辑的歌曲主要是？」选项为：**新创作 / 重新演唱旧歌 / 新旧混合 / 重新录制自己的旧歌 / 不确定**。按场景可简单询问「大部分基本沿用原曲，还是有大量重新改写？」；无需额外填写长篇理由。
- 后台根据**现有政策文件中的五档来源预设**运算。不要凭百分比或曲目数量擅自发明V0.19没有规定的阈值；无法从已知信息唯一确定档位时，不可猜填，应维持未确认状态，提供简单的确认入口；未确认时可以保存评分草稿。
- Spotify元数据并不能可靠确定歌词/作曲是否旧作、是否翻唱；不要假装能完全自动识别。对于混合来源，必要时只要求勾选/选择各曲「新创作／旧歌／旧作重录／不确定」，绝不要求人工输入修正数字。
- 文化理解按规则在后台处理，**未经批准的文化数值修正保持0**；中国/海外选择、中文演唱、方言或传统乐器不能触发自动数字加分。不得因未填文化说明阻止普通打星和导出。
- 如来源/修正不满足正式审查条件，仅内部记录状态；普通评分与图像导出不得被“必须提交审计字数”阻塞，也不得虚称是正式审核发表。

### 第二步：六维打星
- 单页只有6行：**作词／作曲／表演／声音／愿景／语境**。
- 每行右侧是**五颗完整显示的星形**，未选中灰色。点击一颗星左半边得到x.5，右半边得到整数星；手指触摸同样支持。悬停/点击反馈流畅，充分测试手机点击精度。
- **只显示五颗星，不要把半星拆成十个独立星标；不在每颗星下显示数字**，也不显示权重。可用简短的 `aria-label`、键盘控制满足无障碍。
- 评分理由、反证、20字下限、强制证据字段全部**从主界面移除**。如果旧数据库仍保存审计证据，则继续留在数据结构或隐藏的高级功能中，但不得阻止私人打分及导出评分卡。对于“正式发表资格”，不能在无证据情况下伪称已经通过；**图片导出不等于审批发表**。
- 非纯器乐专辑六维均需打星才生成最终数值。纯器乐专辑只在作词一行的简洁更多菜单中允许「不适用」；罕见表演N/A也只能通过明确特殊情境处理，严格遵循旧引擎归一化。未评分和N/A不得混淆。
- 底部唯一主操作「生成评分卡」。自动保存当前进度，允许返回修改风格。

### 第三步：评分卡预览与导出
- 先显示卡片预览，再是**可选短评输入框**。建议120汉字以内，最多200汉字；没有最少字数，不填直接导出。短评更新即时重绘卡片。
- 核心主体：**左侧大专辑封面、右侧六维风向玫瑰图**，二者占卡片主要视觉空间；标题、艺人、年份、总分放顶部或边缘；短评在底部。
- **默认画布1080×1350（4:5）**，优先兼容小红书/Instagram图文；可一键切换 **1080×1440（3:4）** 以适配小红书，以及1080×1080（1:1）作为备选。比例切换仅重排布局、不重新算分。
- 图不要再用尖锐的六角雷达折线作为唯一样式：**默认设计为六瓣饱满、圆润、有节奏的极坐标玫瑰图**（SVG花瓣/扇瓣均可），六瓣径向长度只由六维星级决定；权重只用于最终总分。每瓣有清晰维度名称，图本身不展示百分比。
- 需要统一主题色（例如深墨灰文字、米白底、朱红/砖红作为默认强调色）；允许简洁的明暗/主题选择，但不要做几十个自定义表单。必须保证封面和玫瑰图足够大、文字清晰、视觉留白与层级合理。
- 有短评则显示短评区域；无短评自动收起、让主视觉更舒展。文字过长时不要直接裁切或缩到不可阅读：调整排版或建议切换3:4。
- 支持PNG下载；SVG下载可作为辅助。测试远程封面在导出中不丢失；若Spotify图片涉及跨域或授权限制，采用合规的资源加载方案或提示使用本地上传，**不要通过不安全的CORS绕过方式实现**。
- 总分按现有引擎精确计算并最终half-up两位。短评与视觉主题不能影响分数。

## 2. Spotify搜索集成（重要技术约束）

- 使用**官方Spotify Web API**，先检查开发者账号权限、现行授权模式、服务条款、各端点实际提供的数据字段与配额。不得假定必有“专辑流派”字段。至少希望支持专辑搜索、艺人、发行日期、封面、曲目、时长、版本区分。
- 首阶段不要求用户注册Spotify或实现在线播放。若可用，采用安全的服务端/Serverless API代理保管Client Secret；绝不能将Spotify Client Secret写入前端代码、Vite公开环境变量或提交到Git。若选用PKCE则按官方规范实现。
- 如果Spotify API凭证尚未配置，请先完成**可工作的搜索UI与真实数据Provider接口**，配合明确标记的本地演示数据和“手动添加”兜底；不得假装搜索已联网成功。不要因为接口未接通就停掉整个界面重构。
- 不以Spotify艺人流派直接当成专辑一级/二级风格，不以Spotify市场可售区域判断艺术家文化来源。对平台中缺少的中国独立作品，手动录入始终可用。
- 尊重Spotify数据使用、封面和署名要求；缓存与导出应遵守现行开发者条款。上线前单独核验API权限和条款。

## 3. 数据与内部质量保证（不可拆掉）

- 保留V0.19只读全球风格权重、33个中国市场索引、一级/二级父子关系、版本快照、N/A、来源和文化修正预算、精确运算、历史结果可复现。
- 前端不显示后台实现细节，不等于删掉后台验证。规则冲突时不要擅自改公式；优先以原有Python参考程序与黄金案例为准。
- 保持IndexedDB保存和自动恢复，支持JSON导入/导出备份。正常操作不显示哈希、算法版本和审核状态；这些字段可只存在于内部记录或「设置→高级／诊断」。
- 评级只产生**私人评分记录**，无需正式发表审核。若既有程序把`publish_eligible`与强制理由绑定，保留该严格判定给未来的公共发表功能，**不要把它作为评分卡PNG导出的必填前置条件**。确保空白审核理由不会伪装成已审核。
- 搜索结果多版本同名时提供发行年份、Album/EP及发行版本辨别，不擅自合并不同实体。所有变更不得丢失用户已经保存的专辑。

## 4. 视觉和交互验收标准（由Codex亲自运行检查）

1. 打开首页，第一眼只有一个专辑搜索框以及近期作品；没有规则说明墙或Slogan。
2. 选择一张Spotify专辑后，封面、名称、艺人、曲目与年份自动填入；无API时明确告知未连接、可手动添加。
3. 风格先一级后二级，两层都可搜索/展开；不会把558个二级风格塞进一个巨长下拉列表。中国优先只影响排序。
4. 普通原创专辑：一路选择风格、点击6行星星、下一步生成卡片，**过程中无需填任何评分理由或触碰百分比**。
5. 点击五颗星左右半部可稳定选3.5、4等值；桌面和手机均可用。N/A与未评分不同。
6. 跨家族多风格EP：从「多种风格」开启逐曲风格选择，后端只聚合权重，专辑仍仅有一组六维星级。
7. 来源修正在后台按现有档位计算；任何无法唯一确定的档位均要求最少量确认，不允许静默猜测或修改固定15%维度。
8. 评分卡默认4:5，专辑封面和六瓣玫瑰图是视觉主体；提供3:4和1:1；短评空时可以导出，输入200字时图片无截断。
9. 远程封面和本地封面导出PNG完整可见，主题颜色统一、没有溢出或模糊。
10. 已保存的旧评分仍可打开，修改或重新导出不丢失历史数据；原有计算测试、黄金样例、构建均通过。

## 5. 实施顺序与交付方式

- **先阅读当前仓库再动代码**，列出将删除/隐藏的旧UI模块和将保留的评分引擎接口。不要另起炉灶。
- **第1批：** 首页、Spotify搜索Provider接口和手动添加兜底；专辑确认页；一级/二级风格选择器。
- **第2批：** 极简六维五星控件；隐藏修正UI并接入规则引擎；自动保存。
- **第3批：** 六瓣玫瑰图、4:5/3:4/1:1导出卡、短评、PNG资源加载。
- **最后：** 跨风格EP、回归测试、移动端测试、说明文档更新。
- 完工前分别运行`npm test`、`npm run build`（按当前仓库实际命令），核对Python黄金案例；如能使用浏览器自动化，做真实点击和导出截图测试。
