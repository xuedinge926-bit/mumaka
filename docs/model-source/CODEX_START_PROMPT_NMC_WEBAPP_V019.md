## 1. 产品定位

这是我个人音乐评论品牌长期使用的**人工主导专辑评价工作台**。主要评价中国/华语市场的流行、摇滚、民谣、R&B、说唱、电子、独立音乐，也要能处理国际音乐。**专辑/EP是评价单位，不能将单曲星级平均成专辑分数。**

产品分为：
- **私人工作台（本期必须完成）**：作品管理、曲目与来源、风格选择、六维打星、证据记录、修正、计算、审稿与数据导出。
- **公开评分卡预览（本期完成基本版）**：六维风向玫瑰图、专辑信息、总分、短评，并支持导出图片；以后扩展为公开乐评网站。

优先做好可靠的评分引擎和编辑工作流，再做漂亮的界面。不要开发登录系统、付费、云数据库、自动抓取唱片信息、AI自动评分或线上多人协作。

## 2. 技术栈与架构

- React + TypeScript + Vite；样式使用 Tailwind CSS（或等价可维护方案）；桌面优先，兼容手机。
- 核心评分引擎写成**与 React UI 完全分离的纯 TypeScript 模块**；UI 不能重新实现一套计算逻辑。
- 用 IndexedDB 持久保存专辑、曲目、证据、六维评分和版本记录；提供 JSON 全量备份及导入恢复。不要只用 React 状态存储重要数据。
- 静态风格数据和政策文件作为**版本化只读输入**，不得修改原始 558 条全球风格权重；保留源版本和数据哈希以便重算。
- 用浏览器 SVG 绘制可复用的六维风向玫瑰图；支持导出 SVG，尽力支持 PNG。图形应优雅、易读，且星级数据与权重数据分开显示。
- 为规则引擎编写单元测试，使用资料包中的 `GOLDEN_CALC_FIXTURES.json` 与 Python 参考实现核对；不能靠目测页面判断公式正确。

## 3. 本期必需页面和功能

### A. 作品库
- 新建、编辑、复制评价记录；包含艺术家、专辑名、发行年份、具体版本、封面（允许本地上传）、作品类型（专辑/EP）、语言与地域标签、曲目与时长。
- 作品列表可以搜索、筛选、排序；清楚显示审核状态，不要内置伪造的已评分专辑。

### B. 风格选择
- 以 **33项中国市场常用入口**为快捷导航，支持搜索全球 **558项二级风格**。
- 快捷索引项只映射到全球 `global_genre_id`，**不能因此建立第二套权重**。
- 选中后展示六维基础权重、风格ID、别名、审核状态、可听辨认依据和易混淆风格排除理由。
- 校园民谣/校园民歌按现行规则映射到当代民谣；西北民谣与西北民歌摇滚只做候选标签，不直接生成新全球风格。
- 中文、粤语、西北方言等语言标签不得自动改变风格权重。中国风/古风必须按实际音乐特征认定。
- 真正跨家族混合的专辑可按逐曲风格聚合**权重**；但仍然只评**整张专辑的一组六维星级**。

### C. 修正及来源审核
- 必须有文化**定性**适配记录；数值文化修正默认 0，当前无已批准档案，不能直接将非零文化修正标为可发表。
- 按 V0.16 已冻结的五档来源修正处理原创、翻唱、传统歌曲、旧作重录；非零修正需填写逐曲词曲来源证据与理由。
- 来源修正不可当作翻唱惩罚；不得因翻唱在词曲星级扣分后再重复扣权重。
- 严格执行两种修正的百分比总和、零和、最低有效权重及固定愿景/语境各15%的边界。
- 显示基础权重、修正量、最终权重和拒绝修正的清晰原因。

### D. 六维编辑器
- 作词 Lyrics、作曲 Composition、表演 Performance、声音 Sound、愿景 Vision、语境 Context。
- 每项按 0.5 至 5 星、每次 0.5 星选择；有独立证据、反证和评分理由输入。
- 必须区分：尚未评价、正式N/A、已打分；不得将未评价当成N/A。
- 4.5/5星需要额外解释为什么达到该档、为什么不是低半星，以及全碟支撑证据。
- 不得将罗大佑、周杰伦、许嵩、鲍勃·迪伦过去的研究性试评分当成正式数据或自动评分依据。

### E. 计算、可视化及状态管理
- 总分 = `sum(各维星级 × 最终权重百分点) / 50`，**精确运算，最终一步 ROUND_HALF_UP 保留两位小数**。
- 对作词N/A（及极少数有充分理由的表演N/A），按参考引擎处理动态70%权重的合法归一化。
- 六项中存在未评价，不得显示可发表的正式总分；允许明确标记的草稿预览，但不要伪装成定稿。
- 展示六维玫瑰图、六维星级、每项百分比、总分、短评、模型版本和审查状态。
- 审查状态区分：草稿 / 研究性候选 / 满足结构化发表条件 / 已人工批准发布。**程序可以校验条件，但不能替代人的艺术审核。**
- 已发布评分必须生成不可静默覆盖的版本快照，修改规则后重新评价应创建新版本。
- 支持导出 JSON、CSV，评分卡 SVG、PNG（若环境允许）。

## 4. 必须自动测试的情景

1. 全球558条权重及中国33入口的引用完整性；不同快捷入口指向同一主风格时不产生重复权重。
2. 方言、地域标签不会自动改变权重；候选风格不得冒充已批准全球ID。
3. 六维全部4星、任何有效权重配置都得到8.00。
4. 来源及文化修正满足零和、上限、有效维度最低权重；非法组合有明确报错。
5. 作词N/A与尚未评价表现不同，正确处理归一化和发表资格。
6. 跨家族聚合仅调整权重，不平均歌曲星级。
7. 半入进位边界计算与Python黄金样例完全一致。
8. 4.5／5星证据不足不能通过发表门禁；非零、未批准的文化数值修正不得发布。
9. 已发布的旧版本不可被重新计算自动覆盖。
10. 断网后本地评分与读取仍可工作；导入/导出后数据没有丢失。

## 5. UI设计要求

界面应像成熟的编辑工作台，而不是工具演示页：中文优先、留白充分、信息密度适中、视觉克制、深浅模式可后补。重点优化从“选风格→确认权重→填证据→六维打星→审核→导出图片”的操作流程。六维风向玫瑰图应成为视觉识别中心，但不能喧宾夺主或掩盖原始数据。
