# 交给 Codex 的直接任务书

请在这个资料包的基础上，实现一个**本地优先、人工主导的新乐评主义六维专辑评价工作台**，第一版不要联网、不要引入自动听音识别或自动评分模型。

**开始之前先读：**
1. `CODEX_START_HERE.md`
2. `CODEX_IMPLEMENTATION_SPEC.md`
3. `FRAMEWORK_AUDIT.md`
4. `MODEL_POLICY_V019.json`
5. `nmc_reference_v019.py` 和 `tests/test_v019.py`
6. `data/CHINA_MARKET_INDEX_33.csv` 和 `data/genre-weights-v0.17-frozen.csv`

## 第一次开发任务

用 React + TypeScript（若现有项目已有技术栈则保持现有栈）做一个可本地运行的最小版本，优先包括：
- 专辑/发行版本创建，人工输入歌曲曲目和作者来源。
- 中国市场33入口快捷选择＋完整全球558条二级风格搜索。显示别名、主库ID、基础六维权重和审核状态。
- 为“校园民谣”显示历史类型辨认条件，映射`genre:contemporary-folk`；“西北民谣／西北民歌摇滚”只列在待审候选，不当新风格。
- 评分前记录文化定性适配和来源审核；非零修正需有证据，非零文化修正因当前无获批档案，不能进入发表资格。
- 六维0.5星步长评分、N/A与未评价状态分开；在同一页面给出每维独立论据区和4.5/5高星审查提示。
- 总分按精确分数计算，最终half-up保留两位小数；显示主风格基础权重与实际权重。无完整六维评分不得展示正式总分。
- 一个简洁的六维风向玫瑰图；可导出PNG/SVG及评分的JSON和CSV。历史已发布版本不可被新规则静默改写。
- 草稿／研究候选／满足结构化发表条件／已正式发表四种状态必须区分，后者必须人工批准。

## 边界

- **不新建三级并置风格**，不为中文或方言平行创建另一组基础权重；不要未经确认把校园民谣设独立全局权重，也不要把西北音乐自动定为新风格。
- 不随意修改现有全球558条基础权重、V0.16来源修正档位、V0.14语境与六维的60条等级规范。
- 不把《范特西》《之乎者也》或其他历史研究评分当作技术验收真值；只有计算/结构用例能做自动测试。
- 不伪称完成真实全碟复听、独立行业使用频率验证或历史接受史核实。
- 优先使用`data/GOLDEN_CALC_FIXTURES.json`把参考Python结果移植到TypeScript，并跑完整单测与边界测试。

**先交一个可运行的最小版本和测试结果，再继续扩展编辑、美化、用户账号、在线发布或自动化功能。**
